# rd viewer

Browser client for rd: vanilla TypeScript, built with Vite and Bun, no UI framework. The wire format mirrors
`crates/rd-proto`, and `docs/protocol.md` is the contract.

```sh
bun install
bun run dev         # http://127.0.0.1:5173; proxies /api and /ws to a gateway on 127.0.0.1:8080
bun run build       # → dist/ (index, viewer, probe, latency, keytest .html + assets/)
bun run typecheck   # tsc --noEmit, strict
bun run test        # vitest; includes the golden vectors in crates/rd-proto/testvectors
bun run format      # prettier
```

For local development, run the gateway as `cargo run -p rd-gateway -- --dev --assets-dir viewer/dist`, or run it
next to `bun run dev`. The dev server serves the gateway's routes too (`/m/{machine}`, `/probe`, `/latency-target`,
`/keytest`) and sends the same COOP/COEP headers, so `SharedArrayBuffer` works. WebCodecs needs a secure context:
use localhost, or HTTPS in production.

## Layout

| Path        | What                                                                                                                                                                  |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/proto` | Binary codec (`bin.ts`) and JSON control types with defensive parsing (`control.ts`)                                                                                  |
| `src/net`   | Session socket (`session.ts`): connect → `session` → `hello` → `start`, PING/PONG, close codes, reconnect backoff; clock offset estimator; HTTP API helpers           |
| `src/video` | WebCodecs pipeline (epochs, discard-ACKs, ACK in the output callback, immediate or rAF drawing); input→photon latency test                                            |
| `src/audio` | Opus `AudioDecoder` → SharedArrayBuffer ring → `AudioWorklet` with an adaptive jitter buffer                                                                          |
| `src/input` | Pointer, wheel and keyboard capture; letterbox-aware coordinates; modifier mapping; reserved chords; pointer lock. `keymap.gen.ts` is generated by `tools/gen-keymap` |
| `src/ui`    | Connect screen, HUD, settings (localStorage per machine), banners, wake lock, the viewer app                                                                          |
| `src/probe` | M0 network probe: tests, analysis and verdict                                                                                                                         |
| `src/pages` | One entry per HTML page                                                                                                                                               |

## Shortcuts in a session

Ctrl+Alt+Shift + **F** fullscreen + Keyboard Lock · **L** pointer lock · **H** stats HUD · **T** latency test · **D**
disconnect. The small ▾ tab at the top of the screen opens the menu and the settings.

To run the latency test, open `/latency-target` on the host, rest the remote cursor on its box, then press the T
chord. The viewer sends F13 and measures how long it takes for the box flip to be painted.

## Keyboard and connection notes

- Keys are sent by physical position (`KeyboardEvent.code`); `src/input/keyboard.ts` holds the key state.
- Caps Lock is synced, not forwarded: the host's lock follows the local one (`getModifierState`).
- Windows: AltGr (Right Alt on US-International, German, …) arrives as Right Option. The extra left Ctrl that
  Windows sends with it is dropped; to tell the two apart, a left Ctrl press is held back until the next key, click
  or scroll (at most 100 ms). A Shift keyup releases both Shifts (Windows omits one when both were down).
- A key released after focus moved to the menu or a banner is still released on the host.
- A session socket that cannot open within 10 s is retried. If it is refused because the sign-in expired (or the
  user is not allowed), the viewer stops and asks for a page reload instead of retrying forever.
